# Google Cloud SDK: обновление до 584.0.0 и исправление Unknown в WinGet

PowerShell reference recipe for updating Google Cloud CLI with a copied bundled Python and repairing its Windows uninstall `DisplayVersion` metadata. No WinGet pinning.

**Статус на 10 сентября 2026 года: сохранён итоговый сценарий разбора; успешное выполнение последней команды на исходном Windows-компьютере пока не подтверждено.** Это не отчёт о завершённом ремонте и не проверенная на всех установках утилита.

## Что здесь находится

- `README.md` — контекст, команда одной строкой, разбор ошибок, диагностика, ограничения и порядок проверки.
- [Update-GCloudAndRepairWinget.ps1](./Update-GCloudAndRepairWinget.ps1) — та же последовательность действий в читаемом многострочном виде. Сообщения и комментарии в файле написаны ASCII, чтобы не зависеть от обработки кириллицы в Windows PowerShell 5.1.

Материал размещён изолированно в ветке `docs/gcloud-winget-version-repair`. Он не подключается к запуску GitMir, не меняет код приложения и не добавляет фоновых задач. Основная ветка репозитория не изменяется этой публикацией.

## 1. Исходная задача и подтверждённые факты

В исходном выводе WinGet была строка:

```text
Google Cloud SDK    Google.CloudSDK    Unknown    584.0.0
```

Здесь `Unknown` — неопределённая установленная версия, а `584.0.0` в столбце доступного обновления — не доказательство, что эта версия уже установлена. WinGet различает установленную и доступную версии; при неопределённой установленной версии для попытки обновления используется `--include-unknown`.[1][2]

В предоставленных результатах запуска подтверждены три обстоятельства:

1. Проверка через `gcloud version --format=json` вернула **583.0.0**, а не 584.0.0.
2. `winget upgrade` для этого пакета завершился сообщением **«Применимый установщик не найден»**.
3. `gcloud components update --version=584.0.0 --quiet` отказался обновляться с используемым встроенным Python и сам предложил `gcloud components copy-bundled-python` с установкой `CLOUDSDK_PYTHON`.

Отсутствие или некорректность `DisplayVersion` в записи удаления — **проверяемая гипотеза**, а не установленный по этим логам факт: исходный дамп этой записи не предоставлялся. `DisplayVersion` является полем сведений об установленной программе; справочник Windows Installer также описывает это поле.[3] Причины ошибки подбора установщика WinGet без его диагностического журнала не установлены.

**Цель сценария:** сначала действительно привести SDK к 584.0.0, затем записать проверенный номер в существующий параметр `DisplayVersion` либо создать этот параметр в существующей записи приложения. Подменять 583.0.0 числом 584.0.0 без обновления нельзя.

Для устранения одного только `Unknown` обновление SDK само по себе не обязательно. Здесь сохранён именно двухэтапный сценарий из разбора, а не режим «исправить метаданные любой текущей версии».

## 2. Условия применения

Сценарий рассчитан на Windows, **64-разрядный PowerShell**, установленный Google Cloud SDK со встроенным Python и доступным менеджером компонентов. Целевая версия жёстко задана как **584.0.0**. Это не обозначение «самая свежая версия».

Для установки SDK на всех пользователей нужен терминал от имени администратора. Запускать обновление следует вне каталога SDK; эти условия указаны в документации Google.[4] Сохраните ту же учётную запись Windows: запуск от имени другого пользователя изменит смысл `HKCU` и может выбрать другую пользовательскую установку.

Перед применением убедитесь, что:

- `gcloud` и `winget` доступны, а в `PATH` нет неоднозначности между разными установками SDK;
- найденная запись `Google Cloud SDK` действительно относится к тому SDK, который запускается командой `gcloud`;
- сохранены исходные сведения о `DisplayVersion` и резервная копия нужного раздела реестра, если требуется обратимость правки.

**Важное ограничение:** скрипт проверяет количество записей с точным `DisplayName`, но автоматически не сопоставляет `InstallLocation` с путём запускаемого `gcloud`. Единственная запись по имени сама по себе не исключает наличие второй, незарегистрированной portable-установки. При нескольких установках не запускайте запись в реестр до выяснения соответствия.

Команда Google с `--version` допускает и понижение версии.[5] Поэтому этот файл нельзя регулярно запускать на машине, где SDK уже новее 584.0.0, как средство обновления «всегда до последней».

## 3. Итоговая команда одной строкой

Вставить целиком в PowerShell от имени администратора после проверки условий выше. `CLOUDSDK_PYTHON` пишется с обычным подчёркиванием, **без обратной косой черты**. Переменная `$_` в команде не используется.

```powershell
& { $ErrorActionPreference='Stop'; $old=$env:CLOUDSDK_PYTHON; try { $py=gcloud components copy-bundled-python; if ($LASTEXITCODE -ne 0) { throw 'Не удалось скопировать встроенный Python.' }; $env:CLOUDSDK_PYTHON=([string]$py).Trim().Trim('"'); if (-not (Test-Path -LiteralPath $env:CLOUDSDK_PYTHON -PathType Leaf)) { throw "Копия Python не найдена: $env:CLOUDSDK_PYTHON" }; $p=Start-Process -FilePath $env:ComSpec -ArgumentList '/d /c gcloud components update --version=584.0.0 --quiet' -NoNewWindow -Wait -PassThru; if ($p.ExitCode -ne 0) { throw "Ошибка обновления gcloud: $($p.ExitCode). Реестр не изменён." } } finally { $env:CLOUDSDK_PYTHON=$old }; $json=gcloud version --format=json; if ($LASTEXITCODE -ne 0) { throw 'Не удалось проверить версию SDK. Реестр не изменён.' }; $v=($json | ConvertFrom-Json).'Google Cloud SDK'; if ($v -ne '584.0.0') { throw "Фактическая версия: $v. Реестр не изменён." }; $keys=@(foreach ($root in 'HKCU:\Software','HKCU:\Software\WOW6432Node','HKLM:\Software','HKLM:\Software\WOW6432Node') { Get-ItemProperty -Path "$root\Microsoft\Windows\CurrentVersion\Uninstall\*" -ErrorAction SilentlyContinue | Where-Object DisplayName -eq 'Google Cloud SDK' }); if ($keys.Count -ne 1) { throw "Найдено записей SDK: $($keys.Count). Реестр не изменён." }; New-ItemProperty -LiteralPath $keys[0].PSPath -Name DisplayVersion -PropertyType String -Value $v -Force | Out-Null; winget list --id Google.CloudSDK --exact --accept-source-agreements --disable-interactivity }
```

Для запуска скачанного `.ps1` из его каталога, если выполнение локальных скриптов разрешено вашей политикой:

```powershell
& .\Update-GCloudAndRepairWinget.ps1
```

Файл не меняет Execution Policy. Если политика запрещает запуск файлов, не нужно отключать защиту всей системы ради этого рецепта: сохраняется возможность использовать команду в интерактивной сессии, если это разрешено политиками среды.

## 4. Что делает сценарий

Сохраняет исходное значение `CLOUDSDK_PYTHON` в текущем процессе. Затем запускает служебную команду `gcloud components copy-bundled-python`, которую предложил сам SDK в диагностике. Полученный путь обрезается от внешних пробелов и кавычек, проверяется на существование файла и временно передаётся через `CLOUDSDK_PYTHON`. Назначение этой переменной как способа выбора Python документировано Google.[6]

Обновление запускается через `cmd.exe` с `--version=584.0.0 --quiet`. `Start-Process -Wait` используется для ожидания завершения дерева процессов на Windows; `-PassThru` позволяет проверить код выхода.[7] Установка Python отдельно через WinGet или изменение системного `PATH` не требуются этим сценарием.

Блок `finally` восстанавливает прежнее значение переменной в текущем процессе, в том числе при ошибке. Затем SDK повторно опрашивается через `gcloud version --format=json`.[8] Если фактическая версия не равна 584.0.0, запись в реестр не выполняется.

После этого просматриваются ветки `Uninstall` под `HKCU` и `HKLM`, включая перечисленные в скрипте пути `WOW6432Node`. Выбираются записи с точным `DisplayName = Google Cloud SDK`. Ноль или несколько совпадений приводят к остановке; новый раздел приложения не создаётся.

Для единственной найденной записи `New-ItemProperty -PropertyType String -Force` записывает проверенную версию в `DisplayVersion` как строковое значение `REG_SZ`.[9] В конце выполняется `winget list`, чтобы оператор увидел результат.

**Последний вывод не разбирается автоматически.** Отсутствие исключения PowerShell ещё не доказывает, что WinGet перестал показывать `Unknown`: вывод и код выхода WinGet нужно проверить отдельно.

## 5. Почему предыдущие попытки не решили задачу

| Попытка | Результат и вывод |
| --- | --- |
| `winget pin add` | Решает другую задачу: ограничивает обновления, а не сообщает WinGet фактическую установленную версию. Для исправления метаданных не подходит.[10] |
| Сразу требовать 584.0.0 и писать реестр | Проверка обнаружила 583.0.0 и остановилась. Защита от ложных метаданных сработала, но обновления в той команде не было. |
| `winget upgrade --version 584.0.0` | WinGet не нашёл применимый установщик. Факт ошибки известен; её точная причина не доказана. |
| `gcloud components update --quiet` с исходным Python | SDK прямо сообщил, что не может использовать встроенный Python для этого неинтерактивного обновления. |
| Копия Python → временный `CLOUDSDK_PYTHON` → обновление → проверка → реестр | Сохранённый итоговый сценарий. Подтверждение его успешного завершения на исходной машине пока отсутствует. |

В некоторых вставленных ранее командах появлялось `\_` вместо `_`. Это отдельное искажение текста при копировании, а не синтаксис PowerShell, который следует воспроизводить. Оно не объясняет ошибку встроенного Python: та возникла на этапе обновления, до поиска записей реестра.

## 6. Диагностика до и после запуска

Версия CLI, разрешение команды и разрядность процесса:

```powershell
gcloud version --format=json
Get-Command gcloud -All | Select-Object CommandType, Source
[Environment]::Is64BitProcess
winget list --id Google.CloudSDK --exact --accept-source-agreements --disable-interactivity
```

Чтение подходящих записей реестра без изменений:

```powershell
& {
    foreach ($root in 'HKCU:\Software', 'HKCU:\Software\WOW6432Node', 'HKLM:\Software', 'HKLM:\Software\WOW6432Node') {
        Get-ItemProperty -Path "$root\Microsoft\Windows\CurrentVersion\Uninstall\*" -ErrorAction SilentlyContinue |
            Where-Object DisplayName -eq 'Google Cloud SDK' |
            Select-Object DisplayName, DisplayVersion, InstallLocation, PSPath
    }
}
```

Если нужно исследовать среду Google подробнее, используйте локально:

```powershell
gcloud info --anonymize
```

Google описывает `--anonymize` как уменьшение объёма персональных сведений.[11] Это не гарантия полной очистки: перед публикацией журналов всё равно проверьте их вручную. Не публикуйте токены, `application_default_credentials.json`, OAuth refresh token, файлы конфигурации с секретами и полный приватный контекст.

После выполнения требуются **три независимые проверки**: `gcloud` сообщает 584.0.0; соответствующая запись реестра содержит строковый `DisplayVersion` с 584.0.0; WinGet показывает 584.0.0 в столбце установленной версии вместо `Unknown`. Это критерии приёмки, а не уже полученные результаты.

## 7. Откат и границы изменений

**Автоматической резервной копии и транзакционного отката нет.** До запуска через редактор реестра сохраните именно найденный раздел `Uninstall`, отметьте исходное значение и тип `DisplayVersion`, а также факт отсутствия параметра, если его не было.

Для отката только метаданных восстановите прежние значение и тип в том же разделе. Если параметра до запуска не существовало, удаляется только добавленный `DisplayVersion`, не весь раздел приложения. Импорт `.reg` сам по себе не удаляет новые параметры, которых в экспортированном файле не было; это нужно учитывать при возврате к состоянию «параметр отсутствовал».

Это **не откат установленного SDK**. Если обновление завершилось, а поиск записи реестра затем дал ошибку, SDK уже мог измениться. Сообщение «Реестр не изменён» означает, что до собственной операции записи скрипт не дошёл; оно не обещает отсутствие побочных действий установщика Google.

Копия встроенного Python не удаляется этим скриптом. Путь, возвращённый Google, нельзя без проверки трактовать как каталог, который разрешено рекурсивно удалять.

Сценарий не создаёт и не снимает WinGet pins, не устанавливает постоянную переменную окружения и не включает автоматическое обновление по расписанию. Если ранее был ошибочно создан pin, его наличие проверяется отдельно:

```powershell
winget pin list
```

Удаление только pin этого пакета при подтверждённой необходимости:

```powershell
winget pin remove --id Google.CloudSDK --exact
```

Запись `DisplayVersion` не исправляет автоматически все причины сопоставления пакетов в WinGet и не гарантирует, что следующие версии установщика будут поддерживать этот параметр правильно. Если `Unknown` остаётся, нужны диагностика и проверка соответствия установки, а не повторная запись желаемого номера наугад.

## 8. Общая команда обновления через WinGet

Исходная команда для попытки массового неинтерактивного обновления:

```powershell
winget upgrade --all --silent --accept-package-agreements --accept-source-agreements --include-unknown --include-pinned --disable-interactivity
```

Она относится к доступным обновлениям в источниках WinGet, а не ко всем существующим программам и не обязательно к новейшей версии на сайте производителя. `--include-pinned` включает обычные, неблокирующие pins; блокировки и ограничения версий не следует считать автоматически снятыми. `--include-unknown` разрешает попытки обновления пакетов с неопределённой версией.[1][10]

Это разовый запуск, не планировщик. `--silent` и отключение интерактивности не устраняют ошибки установщиков, отсутствие подходящих пакетов или недостаточные права. Исправление Google Cloud SDK выше — отдельная процедура для наблюдавшейся ситуации.

## 9. Проверенность и дальнейшее сопровождение

Подтверждены предоставленные сообщения об ошибках и значение 583.0.0 из исходной проверки. Назначение публичных команд и параметров сверено с документацией Google и Microsoft.

`copy-bundled-python` в этом материале обоснована непосредственно подсказкой установленного SDK, а не обещанием её постоянной доступности в публичном интерфейсе всех будущих версий. Если команда отсутствует в другой сборке, дальнейшая последовательность неприменима без повторной диагностики.

При публикации не выполнены: запуск PowerShell на Windows, обновление реального SDK, чтение и изменение реестра исходной машины, проверка исчезновения `Unknown`, автоматические тесты и проверка синтаксиса штатным парсером PowerShell. Не присваивайте этому рецепту статус «протестировано на Windows», пока не получены соответствующие результаты.

Чтобы подтвердить конкретный запуск, достаточно приложить очищенные сведения о версии Windows и PowerShell, версии WinGet, фактическом SDK до/после, выбранной записи реестра и финальном выводе `winget list`. Новые целевые версии требуют повторной проверки; простая замена 584.0.0 не является доказательством совместимости.
